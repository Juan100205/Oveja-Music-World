## 15:30 — Auditoría "contenido de Ciudad Musical no aparece en el mundo"

**Acción:** Se auditó el flujo completo de visibilidad del mundo (`/escuela`) tras el reporte "subí contenido en ciudad musical nivel 3 y no me aparece nada en el mundo; alumnos a veces ven ningún curso asignado".

**Diagnóstico con queries reales del usuario en Supabase:**
1. Instrumentos: los 6 están `activo: true`; `introduccion` → `curso_id='ciudad-musical'` (nombre editado a "Ciudad Musical"). → descarta filtro `activo`.
2. Usuarios: 6 alumnos tienen `cursos_acceso` y `clases_acceso` **vacíos** (nunca se les asignó acceso — no es bug, es dato). El resto tiene el mapeo curso↔instrumento correcto (el toggle dual del admin funciona). Ningún `teacher` tiene acceso a `ciudad-musical` (el que sube el contenido es el admin).
3. Contenido: curso `ciudad-musical` tiene 4 módulos (Introducción, Nivel 1, Nivel 2, Nivel 3 `f99fc310…` con 11 secciones/11 recursos, `zona: null`) → los datos SÍ están correctos en la DB.

**Brechas confirmadas (arquitectura):**
- **Doble sistema de acceso sin reconciliación:** el mundo filtra por `clases_acceso` (ids de instrumento) pero la edición de contenido/panel teacher filtra por `cursos_acceso` (ids de curso). Usuarios con solo un campo no ven contenido aunque puedan editarlo. Fix recomendado (NO aplicado): visibilidad = `isAdmin || clases_acceso.includes(id) || cursos_acceso.includes(curso_id)` + backfill SQL.
- **Race de carga:** el panel mostraba "Contenido próximamente" mientras el fetch a `/api/content` estaba en vuelo, y si el fetch fallaba silenciosamente (`catch(() => {})`) quedaba vacío para siempre con mensaje engañoso.

**Arreglo aplicado (brecha de UX/carga, lo que pidió el usuario):** en `src/app/escuela/page.tsx`:
- Estados `modulosError`/`modulosReload` y `gymError`/`gymReload` para clases y gym.
- El loading ahora se **deriva** en render (`modulosCargando = !!claseSeleccionada?.cursoId && !modulosDb[cursoId] && !modulosError`) para cumplir la regla React Compiler `set-state-in-effect`.
- Fetch de módulos: ya no es silencioso; si la respuesta no es válida → `modulosError = true`; el catch también marca error. El gym guarda `[]` para no re-fetch.
- Render de ambas listas: **"Cargando mundo…"** → **"No se pudo cargar el contenido" + botón "Reintentar"** → "Contenido próximamente" (solo si de verdad está vacío).

**Verificación:** `npx eslint src/app/escuela/page.tsx` → solo los 3 errores React Compiler pre-existentes (365, 373, 380), ninguno nuevo. `npm run build` → ✓ Compiled successfully.
