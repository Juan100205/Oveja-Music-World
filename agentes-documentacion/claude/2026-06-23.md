## 16:00 — Mejoras en visor de recursos y upload a Supabase Storage

**Acción:** Se implementaron tres mejoras solicitadas por el usuario:

1. **Visor PDF nativo**: Los recursos tipo `pdf` ahora se renderizan con Google Docs Viewer (`docs.google.com/gview?url=...&embedded=true`) en vez de iframe directo, resolviendo el problema de que los PDFs no se abrían.
2. **Transformación de URLs para juegos**: Los enlaces de Scratch se transforman automáticamente a formato embed.
3. **Upload de archivos a Supabase Storage**: Nuevo endpoint `POST /api/admin/content/upload` y botón "Subir archivo" en el modal de recursos del admin.

**Archivos tocados:**
- `src/app/escuela/clase/[instrumento]/page.tsx` — `getEmbedUrl` ampliada con soporte PDF (Google Docs Viewer) y Scratch embed
- `src/app/escuela/gym/[instrumento]/page.tsx` — Ídem
- `src/app/escuela/visor/page.tsx` — Ídem + label de botón actualizado ("Abrir en nueva pestaña")
- `src/app/api/admin/content/upload/route.ts` — Nuevo endpoint para subir archivos a Supabase Storage (bucket `recursos`)
- `src/app/admin/ContentManager.tsx` — Agregado estado `uploading`, función `handleUpload`, input file oculto + botón "Subir archivo" en `RecursoModal`; importado `Upload` de lucide-react
- `agentes-documentacion/README.md` — Creado
- `agentes-documentacion/INSTRUCCIONES-PARA-AGENTES.md` — Creado
- `agentes-documentacion/claude/2026-06-23.md` — Este archivo

**Contexto:** Los PDFs no se abrían porque la mayoría de hosts bloquean iframes (`X-Frame-Options: DENY`). Google Docs Viewer actúa como proxy. Los juegos de Scratch tampoco funcionaban porque la URL normal de Scratch no es embeddable. No existía mecanismo para subir archivos al sistema.

**Pendiente / Próximo paso:** El usuario debe crear el bucket `recursos` en Supabase Storage (dashboard → Storage → New Bucket → público) y configurar las políticas de acceso (INSERT para admin, SELECT público).

**Estado:** ✅ Completado
